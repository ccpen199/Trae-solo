# 3C设备上门维修O2O服务平台 产品需求文档

## 1. 项目概述

### 1.1 项目背景
构建一个专业的3C设备上门维修O2O服务平台，连接用户与认证工程师，提供智能故障诊断、工程师调度、维修过程监控、二手设备回收等全链条服务。

### 1.2 核心目标
- 实现故障智能初筛，提高维修效率
- 优化工程师调度，降低运营成本
- 全程监控维修过程，保障服务质量
- 建立二手设备回收体系，拓展业务边界

## 2. 核心实体模型

### 2.1 工程师(Engineer)
- 基本信息：姓名、电话、身份证号、入职日期
- 技能认证：证书编号、认证等级、认证有效期
- 服务能力：服务半径、历史维修成功率、响应时间
- 装备管理：装备编号、装备状态、最后校准时间
- 位置信息：实时LBS坐标、服务区域

### 2.2 设备故障(Fault)
- 症状代码库：故障代码、症状描述、常见设备类型
- 诊断树：主板芯片级诊断流程、检测点、判定标准
- 维修方案：知识图谱关联、预计工时、配件需求、费用估算

### 2.3 维修订单(Order)
- 订单信息：订单号、用户信息、设备信息、创建时间
- 故障预判：预判准确率、TOP3故障假设、置信度
- 维修过程：工程师ID、预约时间、实际到达时间、完成时间
- 配件溯源：原厂配件溯源码、使用记录、序列号
- 维修凭证：维修前后对比图哈希值、全程录像索引
- 状态流转：待接单 → 已接单 → 维修中 → 待确认 → 已完成 → 已评价

### 2.4 二手机库存(UsedDevice)
- 基本信息：设备型号、IMEI、收购价格、入库时间
- 质检报告：OCR识别结果、功能检测项、外观评级
- 估价模型：估价参数、折旧系数、市场参考价
- 翻新记录：工艺类型、操作人员、材料消耗、质检结果

## 3. 核心功能模块

### 3.1 故障智能初筛引擎
- **多模态输入**：文字描述、语音口述(转文字)、图片上传(视觉识别)
- **智能分析**：基于症状代码库匹配TOP3故障假设
- **置信度计算**：综合多源输入计算各故障的可能性
- **输出结果**：故障描述、预估费用、推荐维修方案

### 3.2 工程师调度模块
- **LBS定位**：实时获取工程师位置，计算距离用户的距离
- **技能匹配**：根据故障类型匹配具备相应技能的工程师
- **配件检查**：验证工程师是否携带所需配件
- **最优指派**：综合距离、技能、评分、空闲状态进行排序

### 3.3 维修过程监控
- **强制录像**：维修全程必须录像，不可中断
- **时间戳摘要**：自动识别关键节点生成摘要片段
- **哈希验证**：维修前后对比图存入区块链式哈希
- **实时同步**：维修进度实时推送给用户

### 3.4 后台运营管理
- **工程师能力雷达图**：技能覆盖、维修成功率、用户评分、响应速度、配件利用率
- **区域故障热力图**：按地理位置展示故障类型分布
- **配件耗损预测**：基于历史数据预测配件需求
- **自动外呼系统**：维修完成后自动回访，收集用户评价

## 4. 用户角色与权限

### 4.1 普通用户
- 提交维修申请
- 上传故障描述/图片
- 查看订单状态
- 评价维修服务

### 4.2 工程师
- 接受/拒绝订单
- 查看维修方案
- 上传维修记录
- 管理个人技能

### 4.3 运营管理员
- 订单管理
- 工程师管理
- 故障库维护
- 数据报表查看

### 4.4 系统管理员
- 用户权限管理
- 系统配置
- 日志审计

## 5. 非功能需求

### 5.1 性能要求
- 页面响应时间 < 2秒
- API响应时间 < 500ms
- 支持并发用户数 > 1000

### 5.2 安全要求
- 用户数据加密存储
- 接口鉴权认证
- 操作日志可追溯
- 图片/视频文件哈希校验

### 5.3 兼容性要求
- 支持主流浏览器(Chrome、Firefox、Safari、Edge)
- 响应式设计，支持平板访问

## 6. 技术栈选型

### 6.1 前端
- 框架：React 18 + Vite
- UI组件：Ant Design
- 图表：ECharts
- 状态管理：Zustand
- 路由：React Router

### 6.2 后端
- 运行时：Node.js
- 框架：Express.js
- 数据库：SQLite
- ORM：Sequelize
- 认证：JWT

### 6.3 部署架构
- 前端：Vite开发服务器
- 后端：Express + Node.js
- 数据库：SQLite文件存储
